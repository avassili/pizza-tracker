# Repository Instructions (`pizza-tracker`)

These instructions apply to all contributors and coding agents working in this repository.

## 1. Documentation & Story Layout

- **Main Backlog (Top of `docs/`):** Keep the master backlog overview at `docs/BACKLOG.md`.
  - `docs/BACKLOG.md` and `docs/jira-import.csv` are generated by `node scripts/jira-backlog.mjs`. Edit `scripts/jira-backlog.mjs` and re-run the script rather than hand-editing generated outputs.
- **Architecture & Design:**
  - `DESIGN.md` — Phase 1 technical design and AWS Free-Tier topology.
  - `docs/TACTICAL-DESIGN.md` — Normative specification for FSM, DynamoDB single-table layout, persistence expressions, RBAC, and Next.js 15 surfaces. Where `DESIGN.md` and `docs/TACTICAL-DESIGN.md` disagree, `docs/TACTICAL-DESIGN.md` wins.
  - `docs/JIRA-KEYS.md` — Mapping of backlog IDs (`PT-E<n>-F<m>-S<k>`) to Jira keys in project `PTS`.
- **Story Documents (`docs/<epic>/<feature>/<story>.md`):**
  - Store all individual story specifications, implementation plans, acceptance criteria, and verification notes under:
    ```text
    docs/<epic>/<feature>/<story>.md
    ```
  - Examples:
    - `docs/E0/F2/S10-dynamodb-structure.md`
    - `docs/E1/F1/S01-create-order-server-action.md`
  - Every story document should list its Jira key (if applicable), Epic/Feature/Story IDs, design references, affected files, acceptance criteria, and verification commands.

## 2. Architecture & Code Boundaries

- **Hexagonal Architecture:**
  - `src/domain/**` must remain pure and side-effect free. It must never import `@aws-sdk/*`, `next/*`, `react`, `react-dom`, or `@/infra/*` (enforced via ESLint `no-restricted-imports`).
  - `src/infra/dynamodb/keys.ts` is the single source of truth for all DynamoDB `PK`, `SK`, `GSI1`, and `GSI2` key builders and item mappers.
- **Next.js 15 Conventions:**
  - `headers()` and route `ctx.params` are asynchronous and must be awaited.
  - Derive `tenantId` and `actor` from server-side session (`getSession()`), never from client arguments.
- **AWS Free-Tier Constraints:**
  - DynamoDB tables and GSIs use `PROVISIONED` billing (`5 RCU / 5 WCU`), never `PAY_PER_REQUEST`.

## 3. Verification Commands

Run these checks after code or script changes:

```bash
npm run typecheck
npm run lint
npm test
```

For local database verification against DynamoDB Local:

```bash
npm run db:init
npm run db:sample-order
```
